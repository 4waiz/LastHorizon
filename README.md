# LastHorizon

A peaceful stylized third-person exploration game. You play a kid in a straw
hat on a quiet coastal road one summer afternoon — there is nowhere to be and
nothing to fight. Walk up the hill, look around, and find five keepsakes
people left behind.

Built with Three.js, TypeScript and Vite. **Every asset is original**: the
character, buildings, props and vegetation are generated by Python scripts
that drive Blender, the shaders and materials are hand-written, and the
soundscape is synthesised in the browser with the Web Audio API over two
original music beds. Nothing is downloaded, scraped or derived from any
third-party source. Full provenance is in [docs/ASSET_LICENSES.md](docs/ASSET_LICENSES.md).

## Controls

| Input | Action |
| --- | --- |
| `W` `A` `S` `D` / arrows | Walk (relative to the camera) |
| `Shift` | Run |
| `Space` | Jump |
| `E` / `F` | Interact — sleep in the bed |
| Drag the mouse | Orbit the camera |
| Scroll wheel | Zoom, within limits |
| `Esc` | Close the info panel / release pointer lock |

A radar sits bottom-left: it rotates with you, showing roads, houses and any
keepsakes you have not found yet. It hides while you are indoors.

On a touch screen: joystick bottom-left, jump and run bottom-right, drag
anywhere else to look. Push the stick past ~78% to run without using the
button.

The tile column, top right: sound, graphics quality, time of day, info, and
fullscreen — with the keepsake counter underneath.

## Architecture

```
src/
  main.ts                  entry point, WebGL capability check
  core/
    Game.ts                frame loop; owns and orders every subsystem
    Renderer.ts            WebGLRenderer setup, DPR cap, resize
    AssetManager.ts        loads the five GLB packs, indexes roots by name
    InputManager.ts        keyboard / mouse / wheel / virtual stick state
    AudioManager.ts        the whole soundscape, synthesised at runtime
    Settings.ts            quality presets, device detection, persistence
  world/
    World.ts               hand-authored layout; builds the collision set
    Terrain.ts             heightfield, vertex colouring, height queries
    RoadSystem.ts          road splines, the road distance field, markings
    Environment.ts         sun, ambient, fog, and the day/night cycle
    Sky.ts                 gradient dome, sun disc, stars, drifting cumulus
    Vegetation.ts          composed instanced placement + grass
    Birds.ts               instanced flocks with a shader wing-flap
    Collectibles.ts        the five keepsakes and their persistence
  player/
    Player.ts              model, rig and subsystems bundled together
    PlayerController.ts    input + camera basis -> motion
    PlayerStateMachine.ts  idle / walk / run / jump / fall / land
    PlayerAnimator.ts      clip selection, crossfades, speed matching
  camera/
    ThirdPersonCamera.ts   spring-damped orbit follow
    CameraCollision.ts     distance probe + occluder dithering
  physics/
    CollisionWorld.ts      one merged static BVH
    CharacterMotor.ts      capsule integration, grounding, slopes
  graphics/
    ToonMaterial.ts        the material system (banding, wind, fade)
    StylizedShadows.ts     soft contact shadow under the character
    PostProcessing.ts      optional grade pass (High quality only)
  utils/                   pure maths and disposal helpers
scripts/blender/           the generators for every model in the game
```

### Notes on the design

**One material factory.** Everything routes through `makeToon()`, which shares
a single 3-band gradient ramp so the whole scene bands identically under the
sun, and caches by value so a hundred imported meshes collapse onto a handful
of shader programs. Materials are shared objects — if you intend to configure
one further, pass an `id` so you get your own.

**One collision BVH.** `CollisionWorld` merges purpose-built *proxy* meshes —
boxes for houses, cylinders for trunks, squat boxes for boulders — rather than
the render meshes. The tree stays small, the player can't get wedged in a
window recess, and road markings can never produce a collision bump.

**The road field.** The road splines are rasterised once into a grid holding
distance-to-carriageway and road elevation per cell. Terrain reads it to
flatten its corridor, vegetation reads it to stay off the tarmac, and the
footstep audio reads it to pick a surface. One structure, no per-frame
closest-point-on-spline searches.

**Tunnelling.** Depenetration always pushes toward the *nearest* surface, so a
single large step past a thin wall's mid-plane gets ejected out the far side.
The motor substeps and also sweeps ahead of each substep, clamping the step to
stop short of the first hit. There is a test for this at 60 m/s.

**Buildings sit on levelled pads.** Seating a house at the terrain height of
its centre leaves the downhill corners hanging in mid-air on any slope. Each
placement declares a footprint that `Terrain` flattens *before* it computes
its grid, ramping back to natural ground around the edge. That also gives the
enterable house a flat floor.

**Interiors are a separate cell.** Every front door shows a "Go inside"
prompt and teleports into one shared, well-detailed room that lives 600 m
above the terrain. That is deliberate: the heightfield is ~2 m per cell, far
too coarse to hold a house-sized platform reliably flat, so any floor built on
it ends up partly buried on a slope. Lifting the room out of the terrain
removes the problem and lets one room be worth detailing. Pressing `E` at the
bed lays the character down, holds the shot for a beat, then fades the clock
round to dawn.

**The interior windows are real.** `WindowPortal` renders the outdoor world
into a half-resolution target from a camera that mirrors yours through the
rigid room-to-world transform, sampled in screen space. Because both cameras
share a projection matrix the result is geometrically exact — the view
parallaxes as you move, the way a window does.

**Day and night.** A single scalar (`time`, 0..1) drives a colour script that
produces the sun angle and colour, ambient fill, fog, sky gradient, cloud tint
and street-lamp glow. Lamps get an emissive material and a soft ground pool
everywhere, plus a small pool of real point lights reassigned each frame to
whichever columns are nearest the player.

## Blender assets

Every model in `public/assets/models/` is generated procedurally. The scripts
live in `scripts/blender/` and are the source of truth — the GLBs are build
output that happens to be committed.

Regenerate the whole kit:

```bash
blender --background --python scripts/blender/build_all.py
```

Or, inside a running Blender (this is how the kit was authored, driven over
Blender MCP):

```python
exec(open("scripts/blender/build_all.py").read())
```

| Script | Output | Contents |
| --- | --- | --- |
| `build_character.py` | `player.glb` | The explorer: 5.0k tris, 20 bones, 6 clips, blink morph |
| `build_buildings.py` | `buildings.glb` | HouseLarge, HouseSmall, HouseSolar, PorchHouse, Shed, HouseOpen (full interior) |
| `build_props.py` | `props.glb` | Streetlight, UtilityPole, Barrier, Bench, Mailbox, FenceSection, RetainWall, Culvert, Bollard |
| `build_nature.py` | `nature.glb` | TreeBig/Med/Small, Palm, DeadTree, BushA/B, RockA/B/C, GrassTuft |
| `build_collectibles.py` | `collectibles.glb` | PaperPlane, ToyBoat, WindChime, OldCamera, StarOrnament |

`lh_common.py` holds the shared palette and primitive builders;
`lh_preview.py` renders the Workbench turnarounds used while art-directing.

Conventions the scripts follow:

- Blender is Z-up; the exporter converts to Y-up. Characters and directional
  props face **-Y in Blender**, which becomes **+Z in glTF**, so
  `rotation.y = atan2(dir.x, dir.z)` works in the game.
- Origins sit on the ground at the footprint centre.
- Colours are authored in sRGB in `PALETTE` and converted to linear on
  material creation, so the exported `baseColorFactor` renders as authored.
- Every primitive is wound counter-clockwise as seen from outside, so the
  meshes survive backface culling.

### The character rig

`build_character.py` builds the mesh from octagonal lofts and rounded boxes,
carves the hair out of an offset copy of the skull with booleans, then skins it
with a deterministic scheme: each mesh part declares which bones may influence
it, and weights fall off as `1/d⁴` over that subset. This is instead of
Blender's bone-heat weighting, which fails silently on low-poly, non-manifold
meshes.

The six clips (`Idle`, `Walk`, `Run`, `JumpStart`, `Fall`, `Land`) are keyed in
code using world-space axis rotations converted into each bone's local space,
so the animation data reads as "swing the thigh forward 26°" rather than
depending on bone roll.

`PlayerAnimator` scales walk/run playback by ground speed against the speed
each cycle was authored for (`WALK_DESIGN_SPEED`, `RUN_DESIGN_SPEED`), which is
what keeps the feet from skating.

## Audio

Two layers. Two original music beds stream from
`public/assets/audio/` — `outdoor.mp3` and `indoor.mp3`, crossfaded as you
move between outside and the interior. If either fails to load the synthesised
bed carries the scene alone, so a missing or blocked file degrades to
"quieter", never to "broken".

Everything else `AudioManager` synthesises from
oscillators and generated noise buffers: a lo-fi chord bed (Dm9-G13-Cmaj7-Am7
under a soft low-pass, with tape wobble on the detune, a bell motif and a
whisper of vinyl hiss), filtered wind,
cicadas by day and crickets by night, birdsong, footsteps that switch timbre
between tarmac and grass, a transformer hum near the poles, and a bell
arpeggio on discovery. Nothing is constructed until the first user gesture, so
autoplay policy is satisfied by construction, and if the AudioContext can't
start the game simply runs silent.

## Performance

- Instanced vegetation, grass, birds and lamp pools.
- Materials shared and cached. Measured at High: **285 draw calls / 482k
  triangles** in the village by day, **377 calls** at night as the lamp
  point-light pool engages, and **183 calls / 780k triangles** indoors — the
  interior is the heaviest scene, not the lightest, because `WindowPortal`
  renders the outdoor world a second time.
- Device pixel ratio capped per quality preset.
- Simulation and audio pause when the tab is hidden; `dt` is clamped so a
  stall can't teleport the character through a wall on the next frame.
- Asset payload: **953 KB of GLB** plus **1.67 MB of audio**, uncompressed.
  Meshopt is wired up in `AssetManager` so a compressed rebuild drops straight
  in; at this size the decoder would cost more than it saves.
- Budgets are documented in [docs/PERFORMANCE_BUDGETS.md](docs/PERFORMANCE_BUDGETS.md)
  and enforced in CI by `npm run check:budgets`.

Quality presets control pixel ratio, shadow map size and distance, vegetation
and grass density, cloud and bird counts, anti-aliasing, the post-processing
pass and fog distance. The starting preset is chosen from device memory, core
count, touch capability and screen size, and can always be overridden.

Changing quality re-instances vegetation and grass live and rebuilds the
collision BVH with it, since trunk and boulder proxies come along.

Terrain resolution is deliberately **not** a quality setting: the same grid
feeds the visible mesh and the collision BVH, so changing it at runtime would
make the player sink or float.

## Known limitations

- The neighbourhood is one hand-authored layout; there is no streaming, so the
  whole world is built up front (about a second on a desktop).
- Only the tile-column UI is localised to English.
- The camera fades foliage and trunks that block the character, but buildings
  are deliberately left solid — walking behind a house hides you briefly.
- All eight doors lead to the same room; there is one interior, not eight.
- The interior windows are live portals onto the outdoor world, rendered at
  half resolution only while you are indoors.
- Chromium logs two `X3557: loop only executes for 1 iteration(s)` warnings
  when Three compiles its shader programs under ANGLE/D3D. They come from the
  translator, not this project.
- Shadows come from a single directional light rather than true cascades, so
  very distant shadows are dropped rather than filtered.
